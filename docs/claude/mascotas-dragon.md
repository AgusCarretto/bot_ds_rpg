**The dragon — the "horse" of EPIC RPG, our way (v0.30.0; `/dragon`, `/dragon-breed @amigo`, `/dragon-train`, `aa dragon`, `aa dragon breed @amigo`, `aa dragon train [n]`; `GameData/DragonRules.cs`, `Modules/DragonModule.cs`, `Repositories/DragonRepository.cs`, `Services/DragonBreedOfferService.cs`, `Database/add_dragons.sql` — run it on a live database BEFORE the v0.30.0 binary: `PlayerBonusService` reads `player_dragons` on every fight and gather and the tavern offers the purchase; harness `dragontest`)** — the owner (2026-10-27): "arrancá a armar el tema del dragón como el horse del epic, agregalo para comprar en la taberna, que sea del 1 al 10 tier, por ahora solo horse breed, o sea criar… armá las mejoras de cada tier como te parezca, sabiendo cómo funciona en el EPIC… tipos: fuerza, defensa, especial, de oro… armá toda la base". My design decisions (all constants in `DragonRules`): **one dragon per account**, bought in the tavern for **3,000 gold** (`ShopPrice`; the option "🐲 Dragón de cría" lives in the SAME select menu as the boxes, because the tavern already uses its five rows; the value is `DragonModule.ShopKey`, not an item) with a RANDOM type (fuerza 30 % / defensa 30 % / oro 30 % / especial 10 %, `ShopOdds`; it cannot be re-rolled: the lever, if wanted, is letting the buyer choose) that starts at tier 1 "Cría". **Four types, each improves ONLY its thing and only against monsters** (it enters through `PlayerBonuses.Dragon`, which duels and the Arena never receive): Fuerza → ATQ (max +12 % at tier 10), Defensa → DEF (+8 %; low on purpose because defense is subtracted flat from every hit, see "Amulets and defense"), Oro → gold of fights (+30 %), Especial → EXP of fights (+25 %); `PlayerBonuses.AttackMultiplier/DefenseMultiplier/GoldMultiplier/XpMultiplier` multiply by it. **Tier ladder** (names Cría, Dragoncito, Joven, Adolescente, Adulto, Curtido, Anciano, Ancestral, Legendario, Eterno): the bonus is `max × curve[tier]` with the convex curve `0.04 / 0.08 / 0.14 / 0.21 / 0.30 / 0.42 / 0.56 / 0.72 / 0.86 / 1.00` (like EPIC's 0 / 5 / 10 / 20 / 30 / 45 / 60 / 80 / 100 / 200 % horse bonus: the good part comes at the end; tier 1 gives under +1.3 % of anything). **Breeding** (the "merge"): two players with the SAME tier, `/dragon-breed @amigo` sends an invitation (2 minutes, `DragonBreedOfferService`, in memory like `/trade`; buttons `dragon_accept:{offer}` — only the invited one — and `dragon_decline:{offer}` — either of the two; the buttons live in `DragonModule` without `[Group]`, so Discord.Net does not prefix the group name); when accepted `DragonRepository.BreedAsync` runs ONE transaction that locks both rows ordered by `discord_id`, re-validates everything (same tier, tier < 10, both rested) and rolls: the chance of going up is `100 / 60 / 30 / 15 / 5 / 2 / 1 / 0.33 / 0.11 %` for tier 1→2 … 9→10 and, EPIC style, a **pity** (`DragonRules.PityCap`: **EXPONENTIAL since v0.31.0** — 0 / 2 / 4 / 8 / 16 / 32 / 64 / 128 / 256 consecutive failures, `PityStart` 2 doubled by `PityGrowth` 2 at every tier, after which THAT dragon's next attempt is guaranteed; the owner: «que sea exponencial, más difícil, sino es muy fácil». It was 0 / 2 / 4 / 7 / 12 / 20 / 30 / 40 / 50, which from tier 6 on reached the cap long before luck mattered); **each dragon of the pair rolls its OWN luck with its OWN streak** (v0.31.0, the owner: «se hace horse breed en pareja pero cada uno con su contador y su probabilidad, puede subir 1 y el otro no»): `BreedAsync` makes two `RollBreed` calls, the dragon that goes up gains a tier and resets its streak, the other adds one failure (**since v0.46.0 the pair and solo failures are TWO counters**: `fail_streak` for pair breeding and `player_dragons.solo_fail_streak` for solo breeding, each with its own pity cap, `PityCap` / `SoloPityCap`, and a tier up of either kind resets both; the owner: «si hizo 5 solo le cuentan para esa cuenta… habría que tener las cuentas separadas»; `Database/add_dragon_solo_streak.sql` BEFORE the v0.46.0 binary, every dragon query reads the column) (`DragonBreedResult.Success` is the inviter's dragon, `SuccessB` the partner's; the old rule was one shared roll with the larger streak of the two). So a pair can end at DIFFERENT tiers, and then it cannot breed together any more (the message says each needs a partner of their own tier); either way both rest **12 hours** (`BreedCooldown`, measured with the database clock). With the pity, going from tier 2 to 3 takes 1.6 attempts on average and tier 1→10 about **424 attempts (~212 days at 2 a day)** per dragon (152 with the old caps): a months-long goal on purpose, and the high tiers need a partner at the same tier (a social bottleneck we accepted; a bulletin board / matchmaking is the obvious next step). **Persistence**: `player_dragons(discord_id PK FK users CASCADE, kind, tier, fail_streak, last_bred_at)`; the Fuego Nuevo does NOT touch it (like pets). `/dragon` shows the type, tier, current and next bonus, the ladder of its type with the current one marked, the pity progress and the rest time. **Second round, same version (2026-10-27, the owner: "para cada tier da una mejora nueva, como epic… que se pueda entrenar al dragón, que sale plata y que cada nivel salga más caro")**: (a) **one NEW perk per tier**, cumulative (`DragonRules.Perks`, applied by `BonusesFor(kind, tier, level)` into `DragonBonuses`): II Ojo de tesoro +4 % drop chance (/hunt, /travel), III Garras de recolector +5 % quantity (/chop, /mine), IV **Aliento final** (once per fight, a hit that would kill leaves you at 1 HP: `ClassPassiveProfile.LastStand` is set in `PlayerCombatProfileCalculator.CombatPassives` only when `bonuses` carries the dragon, so duels and the Arena never get it; it is spent inside `CombatTurnResolver.ResolveTurn` and remembered in `AbilityState.LastStandUsed`, which `ResolveStrike` must copy when a class ability is used; `TurnResult.LastStand` adds a line to the solo fight text; the `/use`-mid-fight counter path does NOT apply it), V Piel de escamas +4 % max HP, VI Instinto de caza +5 % XP, VII Hoguera de oro +5 % gold, VIII Sangre de dragón +3 % ATQ and DEF, IX Fortuna +3 % to drop/gather/gold/XP, X Llama eterna (the type bonus ×1.25).
